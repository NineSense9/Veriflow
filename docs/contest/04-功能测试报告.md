### （二）用例锁住的算法性质

用例覆盖工作流与规格的合法和非法输入、静态规则的反例、缺少审题门不能放行、运行轨迹截断、受约束修复的接受和回滚、沙箱的编译错误、答案错误、超时和通过、对拍不一致、暴力超时与选手答案错误的区分、教练在通过题上不可用、三角色接口，以及竞赛基准的方法学约束。

方法学约束包括：去掉安全维仍跑运行监视；模型载荷不含故障答案；运行时故障不计入静态修复分母；检测和诊断分开；干净底图先通过检查。增量测试比较总状态、问题码和失败约束，结论限于这些字段和测试输入。

## 三、竞赛基准

### （一）如何复现

```
python scripts/competition_benchmark.py
python scripts/competition_benchmark.py --llm-repeats 3
```

第二行只有在环境里配置了评测密钥时才会真正调用模型。当前结果文件对应的是没有密钥的一次运行。结果目录是 experiments/runs/competition/。生成时间是 2026-09-19T07:02:56Z。数据集名称为 competition-v2。冒烟目录里的小样本只用于冒烟。主结果以竞赛目录为准。

### （二）计分如何落到这 55 组

检测把「故障样本上出现异常」记为抓住，把「正常样本上出现异常」记为误报，再合成检测 F1。诊断要求静态问题码等于注入时期望的码，或运行失败文本含约定短语。定位要求问题的节点、边或见证路径碰到被改位置；运行时故障还要求失败项点到被截断的节点。修复接受率的分母排除 5 条运行时专有故障。

表3-1 完整模式结果

| 指标 | 值 | 计数 |
|---|---|---|
| 正常流程 | 5 | 全部没有被误报 |
| 注入故障 | 50 | 全部被检测为异常 |
| 检测精确率 / 召回率 / 检测 F1 | 1.000 / 1.000 / 1.000 | 50 条故障都报了异常，5 条正常流程都没有误报 |
| 诊断正确率 | 1.000 | 50/50 对上约定目标 |
| 定位正确率 | 0.700 | 35/50 点到被改动位置 |
| 可修复案例 | 45 | 5 条运行时故障不进入分母 |
| 修复接受 / 拒绝 | 38 / 7 | 接受率 0.844 |
| 平均静态耗时 | 0.175 毫秒 | 进程内计时，不含网页等待 |
| 平均运行监视耗时 | 0.114 毫秒 | 完整模式每一组都跑了监视 |
| 增量加速 | 未测量 | 不填写倍数 |
| 大模型对照 | 未运行 | 评测密钥未设置 |

检测 F1 为 1，是因为精确率和召回率都是 1。定位仍是 0.700，修复接受率仍是 0.844。三个数字回答三件不同的事。控制台的平均静态核验按一位小数显示，0.175 毫秒在那一格是 0.2 ms。

## 四、消融与大模型对照

### （一）同一套案例的四行

表4-1 消融

| 运行方式 | 检测 F1 | 召回率 | 说明 |
|---|---|---|---|
| 只做结构 | 0.462 | 0.300 | 不跑语义、数据流、安全、可达，也不跑运行监视 |
| 去掉安全维 | 0.889 | 0.800 | 运行监视仍然开启 |
| 关闭运行监视 | 0.947 | 0.900 | 五个静态维都开，漏掉的是 5 条运行故障 |
| 完整 | 1.000 | 1.000 | 静态加运行监视 |

四行的精确率都是 1，5 条正常流程都没有被误报。分数差来自漏报。页面上这四行写成仅结构检查、关闭安全检查、仅静态验证、完整验证。基准页上的确定性静态验证等于仅静态验证，也就是关掉运行监视。完整验证是 1.000。

### （二）全套结果和静态切片

llm_judge.json 里有一份静态切片：去掉 5 条运行时故障后，剩下 45 条故障加 5 条正常流程，静态检测 F1 是 1。这份切片用来给模型对照作参照，模型本身没有运行。全部 55 组在关闭运行监视时，仍是表 4-1 的 0.947。

大模型对照的状态字段是 NOT RUN，原因是 DEEPSEEK_API_KEY 未设置，重复次数为 0，分数字段为空。提示词版本记录为 competition-llm-judge-v3-static。文件注明这条对照永远不作为门禁。

## 七、剩余风险与结论

### （一）剩余风险

特殊评判、交互题、Java 尚未实现。C++ 语法树变异尚未实现，参考解变异打在 Python 上。真实 n8n 和 Dify 尚未接入。增量加速尚未测量。大模型对照尚未运行。安全检查和证据包提供可复核记录，不构成形式化证明。

公网构建若把内存上限压到 1G，Next 构建可能被系统杀掉。发布步骤必须在独立目录构建，并在接口健康之后再切换前端。细节见部署文档。

### （二）测试结论

后端自动化测试在 2026-09-30 通过，共 287 项。竞赛基准的完整模式抓住了全部 50 条注入故障，5 条正常流程没有被误报。定位正确率 0.700。静态修复接受 38 条、拒绝 7 条。只做结构或关掉运行监视都会漏报。大模型没有参加打分。未运行的项目在结果文件和页面上保持空白。
