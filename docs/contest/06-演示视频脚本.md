# VeriFlow 演示视频脚本

- 赛题：第八届 AIC 算法创新赛 · 赛题 2「AI+软件创新」
- 文档类型：演示视频分镜
- 副标题：约 4 分 50 秒，只写要点的按钮，不在录制中途查找地址
- 技术架构：Next.js + FastAPI + Python 验证器 + Docker 沙箱
- 目标环境：1920×1080 浏览器录屏
- 编制日期：2026年09月

官方要求是 MP4，时长严格控制在 3 到 5 分钟，文件不超过 300MB。本脚本目标约 4 分 50 秒，不要超过 5 分钟。

开录前把浏览器准备好：已经用 demo 登录，停在顶栏能看见「控制台」的那一页。按 F11 全屏，缩放固定 100%。不要开 110%，也不要按 Ctrl+K。站点端口是 8081。不要回头看地址，只按下面的按钮。出题质检在「智能对拍」和「需求出题」中间。验证实验室只点第一项「评测基准」。

## 录制前 2 分钟检查

1. 打开控制台确认已登录，页面没有红色错误提示；分辨率 1920×1080、浏览器全屏、缩放 100%。
2. 打开出题质检，选择「缺少审题门 · 生成器直接入库」并点「运行案例」。确认当前案例名、BLOCKED 结论和工作流图都属于案例 1。
3. 切到「静态全绿 · 动态沙箱断流 (典型案例)」并再次运行。确认标题为「静态通过，运行时失败」、静态问题为 0、运行问题为 5，图上能看到红色轨迹断点。
4. 打开沙箱判题，先筛选 WA，再确认 VF1001 的错误详情有输入、期望输出、实际输出三列。录制固定入口为 `/status/23`。
5. 若导航或案例选择状态不对，直接使用备用入口，不要临时点开「最近记录」：案例 1 `/report?demo=case1_order`，案例 4 `/report?demo=case4_runtime`，错误详情 `/status/23`。
6. AI 相关镜头使用提前生成的案例，录制时只运行确定性验证，不等待实时模型响应。开始录制前确认网络正常、页面请求已结束、没有遮挡提示。

## 一、不要说的话

不要说「100% 缺陷拦截」或「全部修好了」。

不要说大模型当了裁判，也不要说大模型对照已经跑出分数。

不要说案例 1 是步骤排反了。图是生成器指向入库，缺审题门，也缺范围守卫。

不要说案例 4 是外部条件没满足，或审题门被删了。轨迹在支付分支之后被截断。通知、审题门和入库都没有执行。

不要把案例 1 的第四条「审题门约束未满足」念成这张图的事实。那句「审题门仍在图上」属于案例 4。案例 1 的图上没有审题门。角落的 6 步、页脚的编译 keyword，案例 1 也不念。

不要念案例 4 列表里的英文 exactly once，也不要念再下面的英文 if branch true then notify。不要报平均静态核验的毫秒数，画面上是 0.2 ms。不要把输入说成同一行。画面上第一行是 3，第二行是 1 2 3。

不要点「巡航演练」，不要点控制台上的「AI 出题质检演示」，不要点「受约束修复」，也不要现场再交代码。下拉改完必须再点「运行案例」，故事板会比图先换字。

## 三、口播

### （一）控制台

已经在控制台。停在标题下面那一排数字上。不要点进去，也不要展开别的卡片。

VeriFlow 做的是一件具体的事：大模型可以出题、写流程，检查器决定过不过。对错由编译出来的约束、静态检查和运行轨迹决定。过不了，门禁就不让入库。下面这排数来自同一套基准。「检测 F1」是 0 到 1 的分数，同时看两件事：故意放进去的故障要抓住，正常流程保持通过。这里是 1，表示这 50 个故障都抓住了，正常的 5 条没有被误报。旁边的 0.844 是修复接受率：45 条里 38 条在重新检查后被接受，7 条被拒绝。

### （二）缺审题门

点顶栏「出题质检」。刚打开时停在上一次跑过的案例，先不要讲。选「缺少审题门 · 生成器直接入库」，再点「运行案例」。等标题变成「发现问题，发布已拦截」，计数是「共 4 · 静态 3 · 运行 1」，再往下滚。页面会回到顶部。标题下面那句是「静态可达满足，但运行时模拟失败」。案例 1 的静态检查还有三条问题，这句先不念。停的位置是：两个节点都在画面里，AI 测资生成指向题目发布入库；下面能看见缺少审题门、规格动作未满足、缺少上界守卫。再往下就是「审题门仍在图上」，不要让它进画面。顶栏底下会留着一行「6 步」，不念。绿色的「受约束修复」不要点。

这是出题侧的第一刀。图很短，生成器直接连到入库。缺的是审题门，范围守卫也不在这条路径上。问题列表里能看到缺少审题门，也能看到缺少上界守卫，还有一条规格动作未满足。门禁在入库前拦住。要补的是审题门。

### （三）轨迹断了

先滚回上方的下拉框。改成「静态全绿 · 动态沙箱断流 (典型案例)」，再点一次「运行案例」。等标题变成「静态通过，运行时失败」，计数是「共 5 · 静态 0 · 运行 5」。再往下滚，六个节点到同一行就停。指「支付状态分支」，条件是 payment_status 等于 success。它和助教审核通知之间有很小的红字「轨迹在此终止」，用鼠标指，不要点。列表第三条「审题门约束未满足」贴着底边，指它。再往下滚会露出英文 if branch true then notify。exactly once 和「需求 AMBIGUOUS」都不念。

第二刀更严格。这张图静态是过的，审题门也还在。分支条件写的是支付状态等于成功。演示在这个支付分支之后把轨迹截断了。通知、审题门和入库都没有被执行，所以门禁仍然拦截。列表里的审题门约束未满足是其中一条。节点画在图上，只表示它被画出来了。门禁看的是轨迹有没有走到。

### （四）做错题能看见反例

点顶栏「沙箱判题」。没筛选时，上面的红色可能是 RE，不要点。先点筛选「WA」，再点第一条的「查看详情」。不要现场再交新代码。不要点「载入编辑器重试」「前往对拍」，也不要点三列旁边的「携此反例与代码前往智能对拍」。进详情后先核对：输入两行，第一行 3，第二行 1 2 3；期望 6；实际 666。对上再讲。

选手侧也是同一条原则。输入分两行，第一行是 3，第二行是 1 2 3。期望输出是 6，程序打出来的是 666。判定来自沙箱。

### （五）评测基准

点顶栏「验证实验室」，在弹出的菜单里点第一项「评测基准」。1920×1080 的第一屏里，页首检测 F1 是 1.000，说明文字有大模型对照未运行。对照表「完整验证与受约束修复」的修复率是 0.844，「大模型判定对照」是未运行。同一屏还有仅结构检查 0.462，以及「直接接受生成结果」的 0.000。0.000 是不跑检查的对照。口播指页首的 1.000 和修复率 0.844。45 和 7 在底边下面，这一镜不滚。

这些数可以复现。一共 55 组，5 条正常流程，50 条注入故障。检测 F1 等于 1，就是刚才说的：故障都抓住了，正常流程没有被误报。范围就是这 55 组。静态修复接受率是 0.844，45 条里有 7 条补丁没有被接受。大模型对照这一行是未运行。没有评测密钥，这一行就没有分数。模型也不进门禁。

### （六）收束

点顶栏「控制台」，停在标题上。

所以 VeriFlow 的分工是：模型负责提案，检查器负责否决。

## 四、录制注意

分辨率 1920×1080。开录前按 F11 全屏，缩放固定 100%。不要开 110%，不要按 Ctrl+K。每一镜先点到位、画面停稳，再开口。换案例必须点「运行案例」。案例 2 和案例 3 不要加进去。不要点「巡航演练」，不要点控制台上的「AI 出题质检演示」，不要点「受约束修复」，也不要现场再交代码。

控制台第一屏下沿有案例 4 卡片和 VF9001 的 RE，不点，口播只讲上面三格数字。卡片上的「通知步骤未被观察到」也不在这一镜改口。出题质检跑完会回到页顶。案例 1 滚到三条中文问题都在、第四条「审题门仍在图上」还没进来就停。案例 4 六个节点进同一行就停，第三条贴着底边，不要再滚出英文。做题这一镜只讲两行输入和 6、666，不要讲对拍。导出 MP4，控制在 300MB 以内。超了就降码率，不要剪掉评测基准。不要出现环境文件和密钥。
