## 1. 产品概述与定位

### 1.1 背景与痛点

ACM / 校赛训练站能交题、能给出 AC/WA，解决不了这些真实痛点：

- 过公开样例，挂隐藏数据  
- WA 只有 `on test 3`，没有最小反例  
- 对拍要选手自己写生成器、暴力和解脚本  
- 题解一看就会，自己想不出来  
- 测资弱导致假 AC  

现有 AI 编程工具会直接给题解，判定还常靠模型自评。拖拽 Agent 平台把自然语言当运行时，缺类型、缺编译期检查。

### 1.2 产品类型与用户

验流是 **可验证算法训练平台**（Web）。对外像训练站，内核是「编译—对抗—环境裁判」。

| 用户 | 场景 |
|---|---|
| 高校 ACM / 算法课学生 | 看题、提交、对拍、对着反例改 |
| 出题/助教 | 自然语言题意编译成出题图，检查测资强度后再发布 |
| 评委 | 打开公网 Demo，走通主路径，下载对照报告 |

### 1.3 差异化（一句话）

**把大模型当编译器、攻击者和教练，不当裁判。对错由 Docker 沙箱和静态检查说了算。**

| 对照 | 他们 | 验流 |
|---|---|---|
| 纯 OJ | 只判对错 | 最小反例、对拍、变异杀死率、禁剧透教练 |
| Chat 讲题 | 模型自评、直接给题解 | 生成与判定隔离 |
| Dify / Coze | 运行时才爆 | 先编译成带类型 IR，缺审题门当场拦住 |

## 2. 技术架构与创新

### 2.1 系统架构

```
浏览器（训练站）
    │  :80
    ▼
nginx
    /        → Next.js 127.0.0.1:3000
    /api     → FastAPI 0.0.0.0:8010

FastAPI
    编译 / 攻击 / 教练 / 起草 / 提交状态机 / 对拍
    DeepSeek 适配器（无 Key 时本地启发式，可替换）
    IR 校验 + 七条静态检查
    Docker 沙箱（禁网镜像 veriflow-sandbox）

存储
    SQLite + artifacts/
```

仓库按包拆分：`veriflow_ir`、`veriflow_staticcheck`、`veriflow_sandbox`、`veriflow_mutate`、`veriflow_compare`、`veriflow_api`、`apps/web`。规则不写进路由，前端不持有 Key、不本地判题。

### 2.2 角色隔离（创新落点）

| 角色 | 执行者 | 禁令 |
|---|---|---|
| Compiler | DeepSeek / 本地启发式 | 只许吐符合 Schema 的 IR |
| Solver | DeepSeek / 空模板回退 | 不准自称已过隐藏测试 |
| Attacker | 出题侧弱测资规则 + 对拍生成器 | 不准把逃逸参数送进 Docker |
| Checker | 静态检查 + Runner + Docker | **模型不得担任** |
| Tutor | DeepSeek / 启发式 | 不准给完整题解 |

### 2.3 选型依据

- 前端 Next.js + Monaco + React Flow：做题台与出题图画布一体  
- 后端 FastAPI + Pydantic：IR 即 Schema  
- 评测 Docker：时限、内存、禁网；拉不到镜像时可回退进程沙箱  
- 模型 OpenAI 兼容接口，环境变量注入，不绑死一家  

### 2.4 两条主路径共用同一管线

```
自然语言或题目 → IR → 静态检查 → 沙箱执行 → 攻击者再砸 → 只准对着轨迹追问
```

- **方案一（做题）：** 提交 → 公开样例 → 隐藏测资 → 最小反例 → 教练 / 对拍 / 变异  
- **方案二（出题）：** 题意 → 出题图 → 缺审题门或弱测资则不能入库  

校园报销 IR 放在附录，证明 Workflow IR 的 `domain` 可切换，不是为 OJ 特化的死结构。

## 3. 功能设计与实现

### 3.1 核心 AI 功能

1. **出题编译：** NL 或示例 → Workflow IR → 图上标红 → 人工审题门 → 入库  
2. **Solver 起草：** 生成代码后仍走同一提交管线，不绕过沙箱  
3. **苏格拉底教练：** 仅 WA/RE 且已有反例；过滤代码块与「题解」字样  

### 3.2 核心非 AI 功能（环境裁判）

1. 题库 VF1001–VF1030（C++17 / Python3）  
2. 判定 CE/WA/TLE/MLE/RE/AC，WA 必须带最小反例  
3. 对拍：生成器 × 暴力 × 选手，暴力超时记 `stress_error` 不是选手 WA  
4. 变异杀死率：针对 Python 参考解的 AST 小算子  
5. 对照报告导出  

### 3.3 扩展性

- 适配器可换本地 Ollama  
- 语言可加 Java（沙箱镜像扩展即可）  
- IR `domain` 可增加校园流程工具白名单

## 4. 开发测试与部署

### 4.1 开发流程

按可演示切片推进：IR 与静态检查 → 沙箱提交 → 对拍 → 出题画布 → 教练 → 变异与 30 题 → 公网部署 → 前端打磨。

### 4.2 测试

本地：`python -m pytest`（当前 **66 passed**）。  
对照脚本：`python scripts/eval.py`，输出 `artifacts/eval.json`，禁止手填无法复现的表。

### 4.3 部署

Ubuntu 24.04，systemd：`veriflow-api`（8010）、`veriflow-web`（3000），nginx 反代 80。评测镜像 `veriflow-sandbox:latest`。原机 8000 端口上的其他项目未占用。详见 `docs/contest/03-部署说明.md`。

## 5. 应用价值与展望

### 5.1 场景

高校 ACM 训练与算法课：把「过样例假 AC」变成可演示的最小反例和对拍。出题侧把「弱数据直接入库」变成编译期错误。

### 5.2 不足与迭代

- Special Judge、交互题未做  
- C++ AST 变异未做（杀死率打在 `ref.py`）  
- 无 Key 时 Solver/Compiler/Tutor 走启发式，结构化输出质量低于云端模型  
- 展望：本地 Ollama、失败规则账本、SPJ
